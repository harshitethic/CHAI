# Implemented architecture — 0.8.0-alpha.1

Normal signed-in ChatGPT with 6 High remains the reasoning provider. Manager, Builder and Reviewer each have a restricted Chromium view and a saved conversation URL. CHAI sends job IDs through visible composer controls. The authenticated MCP bridge supplies scoped context and accepts schema-validated results. No assistant text, cookies or private model endpoints are scraped. Tool OAuth protects CHAI PC access; it does not supply model inference.

The coordinator runs assignment → proposal → execution → independent review → report, with bounded repair rounds. The task engine persists plans, cursor, effects, grants and role calls in SQLite. Per follow-up, workspace mode permits 12 rounds, 60 role attempts and 144 new actions; extended workspace mode permits 50/250/600; review mode permits 3/15/36. Retrying a persisted role call does not charge a second call. A follow-up stops the current operation, retains applied/uncertain evidence, supersedes never-started actions and changes the role-call revision. Durable latest-check verification survives bounded context compaction. Root project instructions and explicitly inspected files become task context, never authority to change permissions.

## Project runtime

`ProjectRuntime` creates a private independent checkout under application data. It copies bounded source files, excluding credentials, links, dependencies and caches, and preserves local Git history when present. Original files, branch and index remain separate. The legacy file gateway accepts these otherwise-protected application-settings paths only when the exact canonical root matches a recorded isolated task project. Arbitrary sibling settings folders remain denied.

Project terminal tools launch Node, Python, Bash and package managers in Bubblewrap with a writable `/workspace`, clean environment, masked Git metadata and no host home/browser credentials. Network is a separate task grant and includes local services. Sessions stream bounded logs, accept stdin, preserve exit/termination records and support Stop. Declared live ports enable local browser previews. Six processes and a two-hour command limit are not full CPU/memory/disk quotas.

Repository tools provide paginated discovery, source search, ranged reads, SHA256/unique-match patches and Git status/diff/branch/commit. File access uses no-follow descriptor traversal. Commits require native confirmation. GitHub CI and confirmed draft-PR publication use the separately authenticated local `gh` CLI; credentials are never injected into the project process environment. Legacy selected-file Git actions retain their narrower snapshot/index-preserving behavior.

## Browser, desktop and outputs

Task browsers permit owned loopback services and explicitly selected HTTPS origins. Observed references, screenshots and desktop targets are tied to task observations. Local interactive previews use an unprivileged `WebContentsView`; remote content has no CHAI IPC/preload or Node access. Browser uploads and bounded downloads retain confirmation and protected-path checks. Selected-window X11 input validates PID, geometry and observation age. AT-SPI availability depends on the target app. Wayland uses a consented RemoteDesktop/ScreenCast portal session, PipeWire frames and portal input; it does not reuse XWayland input.

PDF, DOCX, XLSX and PPTX generators install pinned libraries in a task-local environment and run inside the project sandbox. Output files are registered with hashes and can be saved/opened from the UI. Layouts are basic; output validation does not imply arbitrary visual quality. Other files generated by project commands can also be registered.

External app connectors use HTTPS Streamable HTTP MCP and optional OS-keyring-encrypted bearer credentials. Redirects and unexpected origins are rejected. Task grants restrict available connections; every remote tool invocation requires native confirmation regardless of server-provided safety annotations. OAuth clients support discovery, PKCE, loopback callbacks, dynamic registration or pre-registered public clients and automatic token refresh; credentials are encrypted. ChatGPT's plugins are separate and do not share credentials with these connectors.

## Work UI and recovery

The renderer displays current/next actions, durable checklist states, actual failed/passing checks and expandable role activity. Terminal, Files, Changes, Preview and Outputs panes reflect runtime evidence. Follow-ups, attachments, provider waiting/retry and source/working-copy locations are visible. No overall completion percentage, hidden model reasoning or ETA is invented.

Tray continuation, notifications and login startup are opt-in. Closing to tray preserves active processes. Opt-in durable sessions use detached Python supervisors and atomic private disk receipts. Full exit/crash preserves those processes; ordinary sessions become interrupted. Effect-key-bound sessions are reattached without relaunch. Stop/Revoke sends commands to the supervisor even after app restart. Opt-in restart recovery only resumes safe checkpoints with an existing grant and connected provider; ambiguous external side effects remain paused. Late provider replies can resume waiting background tasks. Whole-PC reboot is a separate unverified acceptance gate.

The authenticated bridge listens on loopback 40671 behind a user-controlled HTTPS tunnel. Kali uses a dedicated named tunnel/user service. Pairing survives same-origin restart; disconnect revokes it. Task data has private file permissions but SQLite is not encrypted. See SECURITY.md, PRIVACY.md and QA_WORKSPACE_2026-10-19.md for limits and verified evidence.

Host execution is separately opt-in: a native root-bound grant allows commands as the user account outside Bubblewrap with a small environment allowlist. Revocation deletes the grant and stops tracked commands. The renderer includes a host/project selector for manual commands, OAuth sign-in status, portal source selection and durable/budget task controls.
